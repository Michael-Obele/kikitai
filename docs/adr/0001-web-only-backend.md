# ADR 0001 — Web Is the Only Backend

**Status:** Accepted (2026-10-18).
**Context:** Kikitai needs Gmail (`gmail.readonly`, restricted scope), Postgres, Better Auth sessions, and AI keys. Capacitor/Tauri WebViews cannot hold cookies reliably, and native clients must never hold Gmail refresh tokens.
**Decision:** `apps/web` is the only server. It keeps Postgres, Drizzle, Better Auth (Google-only + `bearer({ requireSignature: true })`), Gmail REST, AI client, and TTS cache. All other shells (`apps/mobile`, `apps/desktop`, `apps/android-native`) are thin clients over `https://<web-origin>/api/app/v1/*` with `Authorization: Bearer <token>`. Web keeps cookie sessions; native captures `set-auth-token` on sign-in and rotates on every response that carries it. `requireAppSession` maps "no session" to `401 UNAUTHENTICATED`; native clears stored token on `401`.
**Alternatives considered:** (a) Duplicate DB/auth per shell — rejected: Gmail restricted scope + token encryption (`AUTH_TOKEN_SECRET`) must live in one place; (b) Remote Functions from native — rejected: Tauri/Capacitor shells are `adapter-static` + `ssr: false`, no server routes; (c) JWT-only stateless auth — rejected: Better Auth sessions are DB-backed and revocable, which we want.
**Consequences:** Native shells need `GOOGLE_IOS_CLIENT_ID` / `GOOGLE_ANDROID_CLIENT_ID` allow-list + `APP_SCHEME` deep-links + `TRUSTED_ORIGINS` for `capacitor://localhost`, `https://localhost`, `tauri://localhost`, `http://tauri.localhost`. Gmail consent stays server-side; native only sends identity `idToken` via `signIn.social`.
